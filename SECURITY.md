# Security

Only the latest release receives fixes. This is a local workflow toolkit, not a
sandbox for arbitrary hostile files. Do not execute notebook/Rmd code by default.
Image workers contact the provider selected by the user; keep sensitive material
out of public issues, fixtures and logs.

For a vulnerability, use GitHub's private vulnerability reporting feature if the
repository has enabled it. If unavailable, open a minimal issue asking for a
private contact without including an exploit, secret or private source document.
The publishing checklist includes enabling private reporting before promotion.

Report the affected version, platform, a self-authored reproducer and expected
versus observed behavior. Remove account identifiers and credentials from logs.
